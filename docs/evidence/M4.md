# M4 小说分析适配

## 2026-11-22 OpenAI 多段样章实测

使用 OpenAI 官方 `/v1/responses`、`gpt-6-luna` 和严格 JSON Schema，发送原创短句和含 16 段、453 个 Unicode 码点的样章。样章有同段双人对白、空行、全角空格、emoji 和组合字符。 [复现样章](../../fixtures/dialogue_multiline.txt)

| 实测条件 | 结果 |
|---|---|
| 原实现，固定短句「灯亮了。」 | 1 段、1 个区间，通过。 |
| 原实现，多段样章 | 收到完整且结构有效的 JSON，本地标注规则报告 15 处问题。最先出现的是段尾覆盖不全。第 2 段长 44 个码点，模型只覆盖到 37。另有一段长 32，只覆盖到 30。 |
| 提供本地段长和分段坐标 | 原文覆盖与引用校验通过。抽查 4 句明确对白，有 2 句程砚的对白归给沈禾。 |
| 同时提供说话人线索的位置与新角色示例 | 首次请求通过，1 批提交 39 个区间，新增程砚、许师傅 2 个角色。关闭并重开临时书库后，修订号为 1，逐段拼接与 453 个码点的原文完全一致。抽查中沈禾 1 句、程砚 2 句、许师傅 1 句，归属均与预期一致。 |

最后一次用时 15.8 秒，供应商返回 2,406 个输入 token、2,080 个输出 token。4 句抽查只覆盖这份样章。使用相同配置可运行 `uv run python scripts/probe_llm.py --profile openai --fixture dialogue_multiline` 复测，命令会调用云端并可能计费。

「供应商 → 请求与费用记录」中，`state=received` 表示收到了 HTTP 响应，`validation=passed` 表示该响应通过本地标注校验。`validation=failed` 时，`validation_error` 给出结构字段、原文段或角色引用的具体问题。对已完成但标注有误的回包，在本次请求预算内最多纠正一次，仍失败就保留原有标注。
